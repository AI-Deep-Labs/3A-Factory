# Release Notes: 4.1.0 (Git Branch Safety & Commit-per-Task)

**Release Date:** 2026-08-17

Phiên bản 4.1.0 bổ sung cơ chế **Branch Guard** và **Commit-per-Task** vào vòng lặp implement của 3A-Factory, đảm bảo toàn bộ quá trình develop luôn được thực hiện trên đúng nhánh Git và mỗi task hoàn thành đều được commit nguyên tử (atomic) trước khi chuyển sang task tiếp theo.

---

## Tính năng mới

### 1. Branch Guard (Bảo vệ nhánh Git)

**Vấn đề trước đây:** Không có cơ chế nào ngăn developer viết code trực tiếp trên `main`, `staging`, hoặc `develop`. Điều này có thể dẫn đến code chưa review lẫn vào nhánh chính.

**Giải pháp:** Thêm mandatory gate **trước** khi gọi developer sub-agent lần đầu trong mỗi REQ.

#### Luật bắt buộc:
- ❌ Không được implement trên `main`, `staging`, `develop`
- ✅ Bắt buộc tạo nhánh feature từ `origin/main` trước khi code

#### Branch naming convention:

| REQ type | Prefix | Ví dụ |
|---|---|---|
| Bug / issue / hotfix | `fix/` | `fix/REQ-000007-login-500-error` |
| Refactor | `refactor/` | `refactor/REQ-000010-payment-service` |
| Improve / optimize | `imp/` | `imp/REQ-000012-query-performance` |
| Library update / vendor / chore | `vendor/` | `vendor/REQ-000015-upgrade-deps` |
| New feature (default) | `feat/` | `feat/REQ-000003-user-auth` |

Type được suy luận tự động từ `raw.md` + `analysis.md`. Nếu không rõ, agent hỏi user một câu.

#### Dirty working tree:
- Nếu phát hiện thay đổi chưa commit → **dừng hoàn toàn**
- Yêu cầu user stash / commit / discard
- Đánh dấu manifest `git.branch_guard_status: awaiting_user_action`
- Khi resume session → tự động detect và tiếp tục từ bước này

#### Áp dụng cho nhánh feature khác:
- Nếu đang đứng ở nhánh feature không liên quan đến REQ hiện tại → kiểm tra dirty tree theo cùng logic, sau đó checkout `origin/main` và tạo nhánh REQ mới.

### 2. Commit-per-Task (Commit nguyên tử theo task)

**Vấn đề trước đây:** Không có cơ chế commit tự động sau mỗi task. Code của nhiều task có thể bị gom lại hoặc không được commit kịp thời.

**Giải pháp:** Thêm mandatory gate **sau** mỗi review PASSED, trước khi pick task tiếp theo.

#### Cơ chế:
1. Stage đúng file trong `Expected File Scope` của task (không stage lung tung)
2. Tạo conventional commit theo format:
   ```
   <type>(REQ-NNNNNN): TASK-NNN - <task title>
   
   Refs: <requirement IDs>
   Evidence: docs/tasks/<PACKAGE>/reviews/TASK-NNN-implementation.md
   ```
3. **Không push** — chỉ commit local
4. Ghi commit hash vào manifest: `git.commits.TASK-NNN`

---

### 3. State persistence khi ngắt session

Manifest template được bổ sung section `git`:

```yaml
git:
  working_branch: null          # set khi branch-guard Phase A PASSED
  branch_guard_status: pending  # pending | awaiting_user_action | done
  commits: {}                   # TASK-NNN → short commit hash
```

Khi user tiếp tục REQ sau khi session bị ngắt, PM đọc `manifest.git` và tự động phục hồi đúng trạng thái:
- `branch_guard_status: awaiting_user_action` → re-invoke branch-guard Phase A trước tiên
- `branch_guard_status: done` → skip branch check, tiếp tục từ task hiện tại

## Thay đổi trong workflow

```
[Trước 4.1.0]
approved → developer → reviewer → (done) → developer (task tiếp theo) ...

[Sau 4.1.0]
approved
  → release-manager (branch-guard Phase A) — [LẦN ĐẦU]
  → developer
  → reviewer
  → release-manager (commit TASK-NNN) — [MỖI TASK]
  → developer (task tiếp theo) ...
```

## Upgrade

```bash
npx 3a-factory@4.1.0 --agent=<agent> --force
```

> **Note:** Các REQ đang implement với manifest cũ (chưa có `git` section) vẫn hoạt động bình thường — branch-guard sẽ detect `git.branch_guard_status == null` và xử lý như `pending`.
